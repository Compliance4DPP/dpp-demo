How the check works

The browser only sends the file and shows the answer. Every rule lives in policy/dpp.rego and runs inside Open Policy Agent. A file that passes gets a signed credential, built in policy/vc.rego.

Compliance credential

A compliant file gets a verifiable credential: a signed statement that this file passed the check. A file with any FAIL gets none.

Whoever receives it can verify it against the issuer's public key, without running the check again and without trusting this server.

Changing a single character of the JWT makes verification fail, as does a key that is revoked in or missing from the issuer's DID document. The private key is read from the server's environment and never reaches the browser; without it the credential is returned unsigned.

Shape
Gaia-X ComplianceCredential; returned as vc (JSON) and vc_jwt (signed)
Issuer
did:web:validate.posedio.com, key #2026-v3 by default; set with VC_DID_HOST and VC_KEY_ID in .env
Subject
The id of the DppMetadata submodel that was checked
Rules
IDTA-02099-1 v1.0, with the list of checks that passed
Input digest
SHA-256 of the checked input, so the credential is tied to this exact content
Validity
90 days from the moment of the check

Rule groups

All groups run on every request, and one failing rule does not stop the others. Rules about an attribute only run when that attribute is present. The policy returns the group with every result, so the Check page shows the checks under these same names and in this order.

  1. AAS structure

    The root collections are arrays, every shell has an id and assetInformation, every submodel has an id, all submodel references resolve, and a shell references DppMetadata.

    AAS-*

  2. DppMetadata submodel

    Exactly one submodel with idShort DppMetadata, semanticId …/cds/dppMetadata/1, and no duplicate idShorts inside it.

    STRUCT-submodelSEM-submodelDUP-*

  3. Presence

    The 7 mandatory attributes are present with a non-blank value. facilityId is optional.

    MAND-*VAL-*-nonempty

  4. Types and semanticIds

    Each attribute is a Property with the expected valueType and semanticId …/cds/<name>/1. granularity and lastUpdate also need their supplementalSemanticIds.

    TYPE-*SEM-*

  5. Granularity

    The value is Model, Item or Batch and matches the shell's assetKind (Model → Type, Item → Instance, Batch → Batch).

    VAL-granularity*

  6. contentSpecificationIdsoptional

    If present: a list of xs:string Properties, not order-relevant, with at least one non-empty item and correct semanticIds.

    OPT-*SML-*SEM-item-*

  7. lastUpdate

    A well-formed date-time with a timezone, and that timezone is UTC (Z or +00:00).

    DT-lastUpdate-*

  8. Technical datademo only

    Only runs with "also require technical data"; not part of IDTA 02099-1. Needs a submodel whose idShort contains "technical", with at least 3 elements that carry a value, referenced by a shell.

    TECH-*

Verdict

PASSRule satisfied.
FAILRule violated. Any FAIL makes the file Not compliant.
SKIPOptional attribute missing. Does not affect the verdict.

"Compliant" is OPA's allow field: true when no rule returned FAIL.
